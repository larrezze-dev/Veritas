# T-023 — Catálogo: búsqueda, ficha, comparación, clones, favoritos y exportación (segunda porción de F2)

**Fase:** F2 · **Prioridad:** P1 (SEC-005, SEC-006 parcial, SEC-007, SEC-009) · **Estado de aprobación:** APROBADO (2026-11-03): D1–D10 = A, salvo D7 = B y D10 = A por decisión delegada en mí con el criterio del usuario «el resultado tiene que ser profesional y exacto» (ver «Decisiones delegadas»).
**Posición en el orden:** segunda de las tres entregas de F2 (T-022 aceptado → T-023 → T-024). La puerta de F2 solo se supera con T-024.
**Dependencias:** T-022 (catálogo SQLite v2, importador, `veritas catalog`, ADR-009). **Dependencias de ejecución nuevas: ninguna** (solo biblioteca estándar).

## Objetivo

Poder **consultar un catálogo ya importado**: buscar y ordenar perfiles por serie, nombre, dimensiones, área, inercias y masa; ver la ficha de un perfil; comparar varios; **clonar** un catálogo protegido en uno editable; guardar **favoritos y recientes** sin tocar el catálogo; y **exportar** perfiles conservando origen y licencia. Todo por CLI (`veritas catalog …`), sin GUI y sin asignar perfiles a barras (eso es T-024).

## Hechos comprobados (sobre el código aceptado)

1. `CatalogStore.list_profiles(catalog_id, all_revisions=False)` devuelve la última revisión de cada perfil ordenada por serie y designación; el contenido canónico está en `content_json`, y las columnas derivadas (`area`, `iy`, `iz`, `torsion_constant`, `linear_mass`) existen en el esquema v2.
2. Las dimensiones (`dim_<nombre>`) viven solo en el JSON del perfil, no en columnas.
3. Una propiedad ausente es `None`, nunca 0 (contrato de E1); J nunca se deduce.
4. Un catálogo protegido rechaza **cualquier** escritura; por tanto favoritos y recientes **no pueden** guardarse en el archivo del catálogo.
5. Solo `catalogs/store.py` importa `sqlite3`. `catalogs` no importa `core` al revés, ni `fem`, `gui`, `persistence` ni PySide6.
6. No hay carpeta de usuario ni estado oculto: T-022 fijó `--db RUTA` explícito en cada comando.
7. El importador acepta el formato nativo (columnas con nombre de campo, unidades SI); una exportación CSV en ese formato se puede reimportar sin mapeo.

## Pruebas previstas

- **Filtros:** cada criterio con una fila justo dentro y otra justo fuera del límite (inclusivo); unidades distintas dan el mismo resultado; propiedad ausente excluida y contada (D4); `0` nunca equivale a ausente.
- **Batería sobre las 100 filas sintéticas:** resultados esperados calculados con fórmulas independientes (`fractions`), no con el propio código de búsqueda.
- **Orden:** estable, con ausentes al final y descendente correcto.
- **Ficha y comparación:** todas las unidades y estados; cocientes exactos; «—» cuando falta el dato; referencia entre catálogos.
- **Clon:** contenido igual al origen campo a campo (salvo identificadores); `cloned_from` y enlaces por revisión correctos y verificables (`verify` detecta un enlace roto o un contenido alterado); migración 2 → 3 de un archivo v2 conserva todo; origen sin cambios (hash antes y después); clon no protegido y editable por reimportación; clon de un catálogo protegido; nombre repetido rechazado sin alterar el archivo; fallo a mitad de la copia deja el archivo idéntico byte a byte.
- **Favoritos y recientes:** funcionan sobre un catálogo protegido y no cambian su archivo (bytes idénticos); límite de 20; archivo corrupto → código 2 y sin sobrescribir; guardado atómico.
- **Exportación:** ida y vuelta CSV (exportar → importar en un catálogo nuevo → mismas propiedades en SI); JSON con licencia y estado; no sobrescribe sin `--forzar`; catálogo vacío.
- **Aislamiento de capas:** `query.py`, `userdata.py` y `export.py` sin `sqlite3`, `fem`, `gui`, `persistence`.
- **Golden** de la sesión nueva (UUID, SHA-256 y fecha enmascarados) y `ruff`/`mypy` limpios.
- Códigos de salida como en E2 de T-022: 0, 2 (archivo, uso, referencia inexistente o archivo de usuario ilegible) y 3 (`verify`).

## Detalle de E1 (implementada y aceptada 2026-11-03)

**Entregado:** `catalogs/query.py` (puro), `search`, `ficha` y `comparar` en `cli_catalog.py`, 5 claves nuevas (`catalog.search_range`, `search_order`, `reference_invalid`, `compare_count`, `compare_repeated`), 126 pruebas nuevas y una sesión *golden* propia (`tests/golden/catalogo_consulta.txt`). No se tocó `store.py`, el esquema (sigue v2), `core/`, `persistence`, `fem`, `gui`, `pyproject.toml` ni `uv.lock`; el *golden* aceptado `catalogo_cli.txt` es byte a byte el mismo.

**Decisiones de detalle de E1 (dentro del margen del plan; pendientes de tu aceptación en la puerta):**

1. **Tolerancia de los límites:** inclusivos con una tolerancia relativa de 1e-12 que solo absorbe el redondeo de la conversión de unidades (2000 mm² y 20 cm² son el mismo límite). Se prueba la frontera con valores reales del archivo y con perfiles a 1e-9 de distancia.
2. **`ficha` frente a `show`:** `show` (salida aceptada en T-022) no cambia. `ficha` direcciona por referencia `CATÁLOGO/SERIE/DESIGNACIÓN[@REV]` (la misma de `comparar`), imprime lo mismo que `show` y añade el historial de todas las revisiones (hash corto y fecha del lote). Solo en E2 registrará los recientes.
3. **Referencias:** el catálogo y la serie no pueden contener «/»; la designación sí (`L 50/5`); el sufijo `@REV` solo se interpreta si son dígitos (`@0` es error).
4. **Valores que empiezan por «-»:** `argparse` los toma por opción; se escriben con «=»: `--designacion=-100x`.
5. **Rangos:** `A..B`, `A..`, `..B`, `>=A`, `<=B` seguidos de una unidad separada por espacio; sin negativos (todas las magnitudes son positivas); un valor exacto se pide con `A..A`. `0` como límite no pasa por la conversión de unidades.
6. **Ausentes:** el recuento «Excluidos por falta de dato» solo cuenta los perfiles que cumplen todo lo que se les puede comprobar y carecen de una propiedad filtrada, desglosado por propiedad (un perfil sin dos propiedades suma en ambas).
7. **Orden:** estable; por defecto catálogo, serie y designación (texto sin distinguir mayúsculas); los ausentes van al final también en `:desc`; con `--dim` u `--orden dim_x` la tabla añade la columna de esa dimensión.
8. **Unidades de salida:** siempre SI (m², m⁴, kg/m, m), igual que `list` y `show`. Una opción de unidades técnicas (cm², cm⁴, mm) queda fuera de E1.
9. **Comparación:** hasta 8 perfiles; dos revisiones del mismo perfil sí se pueden comparar, el mismo perfil y revisión dos veces no; el límite de 2 a 8 se comprueba antes de leer el archivo.
10. **Cambios en pruebas existentes (declarados):** `tests/test_catalog_layers.py` añade `query.py` a los módulos puros; `tests/catalog_cli_golden.py` y `test_catalog_cli_golden.py` se amplían con la sesión de consulta sin alterar la anterior (se comprobó con `cmp`). `cli_catalog.py` comparte `PROPERTY_LABELS` con `query.py` y extrae `_revision` de `show` (misma salida; cubierto por el *golden* aceptado y una prueba específica).

**Límites de E1:** sin croquis (TK-022), sin fabricante ni material compatible (TK-023), solo SI en la salida, solo CLI. Clon, favoritos/recientes, exportación y esquema v3 son de E2.

### Prueba manual de E1 (copiable)

```bash
# 1. Catálogo con las 100 filas sintéticas (desde la raíz del repositorio)
uv run veritas catalog create --db t.sqlite --nombre Sint --fuente "SINTÉTICO" --licencia "Sin valor comercial" --edicion 2026
uv run veritas catalog import --db t.sqlite --catalogo Sint tests/data/catalog_synthetic_100.csv --mapeo tests/data/catalog_mapping_example.json --sep ";" --decimal ","
# 2. Buscar y ordenar
uv run veritas catalog search --db t.sqlite --area "9..11 cm2" --orden area:desc
uv run veritas catalog search --db t.sqlite --serie sintet --iy ">=500 cm4" --masa "..12 kg/m" --dim h "100..200 mm" --limite 4
uv run veritas catalog search --db t.sqlite --j ">=0 cm4"          # J ausente: 0 coincidencias y 100 excluidos
uv run veritas catalog search --db t.sqlite --designacion=-100x     # valor que empieza por «-»: con «=»
# 3. Ficha y comparación
uv run veritas catalog ficha --db t.sqlite "Sint/SINTETICO-I/SINT-100x50-4-6"
uv run veritas catalog comparar --db t.sqlite "Sint/SINTETICO-I/SINT-100x50-4-6" "Sint/SINTETICO-I/SINT-260x95-6-8"
# 4. Errores (código de salida 2, mensaje sin plantillas sin rellenar)
uv run veritas catalog search --db t.sqlite --area "20 cm2"
uv run veritas catalog search --db t.sqlite --iy "1..2 mm"
uv run veritas catalog comparar --db t.sqlite "Sint/SINTETICO-I/SINT-100x50-4-6"
```

Comprobaciones: la búsqueda no cambia el archivo (hash antes y después); «Excluidos por falta de dato» aparece solo cuando corresponde; «-» en la tabla significa «dato no disponible», nunca 0.
